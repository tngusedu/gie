# 연구과제 관리 사이트 — Firebase + Google 로그인 판

GitHub Pages(화면)와 Firebase(로그인·자료 저장)를 함께 씁니다. Firebase는 무료 요금제(Spark)로 충분합니다.

## 들어 있는 파일

| 파일 | 역할 | 어디에 쓰나 |
|---|---|---|
| `index.html` | 사이트 화면 | GitHub 저장소에 올림 |
| `firebase-config.js` | Firebase 설정값과 관리자 메일 | 값을 채운 뒤 GitHub 저장소에 올림 |
| `firestore.rules` | 누가 무엇을 읽고 쓸 수 있는지 정한 보안 규칙 | Firebase 콘솔에 붙여 넣음 (GitHub에 올릴 필요 없음) |

## 1. Firebase 프로젝트 만들기

1. https://console.firebase.google.com 에 관리자 Google 계정으로 들어갑니다.
2. **프로젝트 추가** → 이름 입력(예: `gie-research`) → 만들기. (Google 애널리틱스는 꺼도 됩니다.)

## 2. 데이터베이스 만들기

1. 왼쪽 메뉴 **빌드 → Firestore Database → 데이터베이스 만들기**
2. 위치는 **asia-northeast3 (서울)**, 모드는 **프로덕션 모드**로 시작합니다.
3. 만들어지면 위쪽 **규칙** 탭을 엽니다.
4. `firestore.rules` 파일 내용을 전부 복사해 붙여 넣고, 안의 `'관리자메일@gmail.com'` 을 **본인 Google 계정 메일(소문자)** 로 바꿉니다.
5. **게시**를 누릅니다.

## 3. Google 로그인 켜기

1. **빌드 → Authentication → 시작하기**
2. **로그인 방법** 탭 → **Google** → 사용 설정 → 저장
3. **설정** 탭 → **승인된 도메인** → **도메인 추가** → `tngusedu.github.io` 입력
   (사이트 주소가 바뀌면 그 주소의 도메인을 넣습니다.)

## 4. 설정값을 firebase-config.js에 넣기

1. 왼쪽 위 톱니바퀴 → **프로젝트 설정** → **일반** 탭 아래쪽 **내 앱** → 웹 아이콘(`</>`) → 앱 닉네임 입력 → 앱 등록
2. 화면에 나오는 `firebaseConfig = { apiKey: ..., authDomain: ..., ... }` 의 값들을 `firebase-config.js` 의 같은 자리에 옮겨 적습니다.
3. 같은 파일의 `ADMIN_EMAILS` 에 본인 Google 계정 메일을 적습니다. (2단계 규칙에 넣은 메일과 같아야 합니다.)

**`firebase-config.js` 여는 방법** — 더블클릭하면 열리지 않습니다(Windows가 실행하려고 합니다).
- 파일을 마우스 오른쪽 버튼으로 누르고 **연결 프로그램 → 메모장** 을 고릅니다. (Mac: **다음으로 열기 → 텍스트 편집기**) 저장할 때 이름이 `firebase-config.js.txt` 로 바뀌지 않게 주의합니다.
- 또는 파일을 그대로 GitHub 저장소에 올린 뒤, 저장소에서 파일을 열고 오른쪽 위 **연필 아이콘** 을 눌러 값을 고치고 **Commit changes** 를 누릅니다.

이 값들은 공개되어도 되는 값입니다. 실제 보호는 2단계의 보안 규칙이 합니다.

## 5. GitHub에 올리기

1. 저장소(tngusedu/gie)에서 **Add file → Upload files** 로 `index.html` 과 `firebase-config.js` 를 올리고 **Commit changes**.
2. 이전 판에서 쓰던 `data.json`, `data (1).json`, `data (2).json` 은 더 이상 쓰지 않으니 지웁니다.
3. 1~2분 뒤 https://tngusedu.github.io/gie/ 를 새로 고칩니다.

## 6. 쓰는 방법

**관리자**
1. **로그인** 을 눌러 관리자 Google 계정으로 들어갑니다. 이름 옆에 "관리자" 가 붙으면 성공입니다.
2. 왼쪽 **기본 목록 넣기** 로 공통 바로가기를 한 번에 넣습니다.
3. **과제 추가** 에서 과제명·연구기간·마감(주요 일정)·도구 주소와 함께 **공동연구진의 이름과 Google 계정 메일** 을 넣습니다.
4. 과제의 **할 일** 탭에서 할 일을 만들고 담당자와 일정을 정합니다. 일정은 **하루(그날 안에) / 시간 지정 / 기간 / 정하지 않음** 중에서 고릅니다. **달력** 탭에서 회의 일정을 넣습니다.
5. 첫 화면의 **전체 마감·할 일** 에 모든 과제의 마감, 끝나지 않은 할 일, 다가오는 회의가 날짜순으로 모입니다.
6. 저장은 누르는 즉시 반영됩니다. 파일을 내려받아 올리는 과정은 없습니다.

**공동연구진**
1. 사이트에서 **Google 계정으로 로그인** 을 누릅니다. 한 번 로그인하면 그 브라우저에서는 계속 유지됩니다.
2. 참여 과제가 하나면 그 과제로 바로 이동하고, 여러 개면 목록이 나옵니다.
3. 맨 위 **내 할 일** 에서 자기 할 일을 체크합니다. 달력·연구 일정·연구진 명단·도구 목록을 볼 수 있습니다.

## 6-1. 전체 캘린더와 근무시간 (화면 위쪽 메뉴)

- **전체 캘린더**: 관리자는 모든 과제의 회의, 마감, 할 일 마감을 한 달력에서 봅니다. 연구진에게는 같은 자리가 **내 캘린더** 로 보이며 자기 과제 것만 나옵니다.
- **근무시간**: 관리자에게만 보이는 메뉴입니다. 출퇴근 시간을 적으면 휴게시간 규칙에 따라 근무시간이 계산되고, 입력을 멈추면 자동으로 저장됩니다. 달을 바꾸면 그 달의 기록을 불러옵니다. Google Sheets나 Apps Script 주소는 필요 없습니다.
- 근무시간 기록을 쓰려면 **새 `firestore.rules` 를 Firebase 콘솔의 규칙 탭에 다시 붙여 넣고 게시** 해야 합니다. (근무시간 저장 권한이 추가됐습니다.)

## 6-1-1. 관리자 첫 화면의 업무 목록과 과제별 공지

- **내가 담당 중인 업무**: 담당이 관리자 본인인 할 일입니다. 과제의 ‘할 일’ 탭에서 할 일을 만들 때 담당을 **나 (관리자)** 로 고르면 여기에 모입니다.
- **내가 요청한 업무**: 관리자가 연구진(또는 연구진 전체)에게 배정한 할 일입니다.
- 두 목록 모두 **예정된 업무 / 지연된 업무** 탭으로 나뉘며, 마감이 지난 것은 ‘지연된 업무’ 로 넘어갑니다. 여기서 바로 완료 체크와 수정을 할 수 있습니다.
- **과제별 공지**: 과제 화면의 개요 맨 위쪽 ‘공지’ 에서 관리자가 **공지 추가** 로 제목과 내용을 올립니다. 그 과제의 연구진만 볼 수 있고, 제목을 누르면 내용이 열립니다.

## 6-1-2. 연구 문서와 참고 자료 (hwp 등 파일 연결)

Firebase 무료 요금제에서는 사이트에 파일을 직접 올릴 수 없어서, **Dropbox·Google Drive에 올린 파일의 공유 링크를 연결** 하는 방식입니다.

**연구 문서 (과제 화면 → 개요 → 연구 문서)**
1. 한글(hwp) 파일을 Dropbox나 Google Drive에 올립니다.
2. 그 파일에서 **공유 → 링크 복사** 를 합니다. 링크가 있는 사람이 볼 수 있게 공유 설정을 해 둡니다.
3. 사이트의 **문서 추가** 를 누르고 **문서 종류** 를 고르거나 직접 적습니다(연구계획서, 중간보고서, 최종보고서, 그 밖의 이름). 과제마다 필요한 종류만 넣으면 됩니다.
4. 링크를 붙여 넣고 저장합니다. 파일이 아직 없으면 링크를 비워 두고 종류만 먼저 등록해 둘 수 있습니다.
5. 연구진에게는 **내려받기** 와 **열기** 가 보입니다. 새 판으로 바꿀 때는 **수정** 에서 링크만 바꿉니다.

**참고 자료 (할 일, 달력 일정)**
- 할 일이나 일정을 만들거나 고칠 때 **참고 자료 → 자료 추가** 에서 이름과 공유 링크를 넣습니다. 여러 개를 넣을 수 있습니다.
- 할 일 목록과 일정 내용에 자료 이름과 내려받기·열기가 함께 보입니다.

알아 둘 점
- 연구 문서 등록은 관리자만 할 수 있습니다. **참고 자료는 그 과제의 연구진도 추가** 할 수 있습니다(할 일 줄이나 일정 창의 ‘+ 참고 자료 추가’). 누가 올렸는지 이름이 함께 표시되며, 연구진은 자기가 올린 자료만 지울 수 있습니다.
- **내려받기** 는 Dropbox·Google Drive의 **파일** 링크일 때만 나옵니다. 폴더 링크나 다른 사이트 링크는 **열기** 만 나옵니다.
- 파일을 볼 수 있는 사람은 Dropbox·Google Drive의 공유 설정이 정합니다. 사이트에서 지워도 원본 파일은 남습니다.
- 사이트에 파일을 직접 올리게 하려면 Firebase를 종량제(Blaze) 요금제로 바꾸고 결제 수단을 등록해야 합니다.

## 6-1-3. 내 일정: 회사 업무·행사·연가·병가 (관리자 전용)

연구과제에 속하지 않는 일정을 넣는 곳입니다. 관리자에게만 보입니다.

- 첫 화면이나 전체 캘린더의 **내 일정 추가** 를 누르고 종류를 고릅니다: **회사 업무 / 행사 / 연가 / 병가 / 기타**.
- **회사 업무** 는 첫 화면의 ‘내가 담당 중인 업무’ 와 ‘전체 마감·할 일’ 에 함께 나오고, 체크하면 완료됩니다.
- **행사** 는 일정 요약과 달력에 나옵니다.
- **연가·병가** 는 달력에 표시되고, 사용 일수가 자동으로 합산됩니다. 사용 일수는 평일 수로 자동 계산되며 직접 고칠 수 있습니다(반차는 0.5).
- 첫 화면의 **연가·병가** 카드 → **설정** 에서 기준 연도, 연가 발생 일수, 지금까지 이미 쓴 연가·병가 일수를 넣습니다. 그 뒤 사이트에 넣는 휴가는 자동으로 더해집니다.
- **출장** 과 **외부활동** 은 첫 화면의 일정 요약 아래 ‘출장·외부활동’ 카드에 나오고, 필요한 서류가 할 일로 자동 등록됩니다.
  - 일반 출장: 출장신청서 제출(출발 전날까지), 출장복명서 제출(다녀온 뒤 정한 기한까지, 기본 7일)
  - 외부활동 출장: 외부활동 승인요청·출장신청서 기안(출발 전날까지), 외부활동 신고서 제출(다녀온 뒤 10일 이내). 출장복명서는 필요 없습니다.
  - 외부활동 · 온라인 회의: 외부활동 승인요청(전날까지), 외부활동 신고서 제출(회의 뒤 10일 이내)
  - 외부활동 · 서면: 외부활동 승인요청(전날까지)만
  - 출장은 ‘출장 추가’ 에서 외부활동 여부를, 서면·온라인은 ‘외부활동 추가’ 에서 형태를 고릅니다.
  - 서류를 끝내면 카드나 할 일 목록에서 체크합니다. 기한이 지나면 ‘지연’ 으로 빨갛게 표시됩니다.
- 이 일정들은 Google 캘린더로 보내지 않으며, 근무시간 표의 ‘연차’ 칸과도 자동으로 연결되지 않습니다.

## 6-1-4. 일정 알림

- 왼쪽 메뉴 아래의 **일정 알림 켜짐/꺼짐** 으로 켜고 끕니다. 처음 켤 때 브라우저가 알림 권한을 물으면 **허용** 을 누르면 바탕화면(Windows는 화면 오른쪽 아래)에도 알림이 뜹니다. 허용하지 않으면 사이트 화면 오른쪽 아래에만 뜹니다.
- **오늘 일정 알림**: 사이트를 연 날 한 번 뜨고, 닫을 때까지 남아 있습니다. 오늘의 출장·외부활동(목적·시간·장소), 오늘의 회의·행사, 오늘 해야 할 일만 나옵니다. 오늘 해당하는 것이 없으면 뜨지 않습니다.
- 시간이 정해진 오늘 일정은 시작 10분 전에 한 번 더 알려 줍니다.
- **사이트가 브라우저에 열려 있는 동안에만** 동작합니다. 탭을 닫거나 브라우저를 끄면 알림이 오지 않습니다. 같은 알림은 하루에 한 번만 뜹니다.

### 알림 시점 고르기

왼쪽 아래 **알림 시점 설정**에서 고릅니다.

- **오늘 일정 요약**: 그날 사이트를 처음 열 때 한 번 뜨는 요약을 켜거나 끕니다.
- **시간이 정해진 일정**: 정시 / 5분 / 10분 / 15분 / 30분 / 1시간 / 2시간 전 가운데 원하는 시점을 여러 개 고를 수 있고, 고른 시점마다 한 번씩 알립니다. 처음 값은 10분 전입니다.
- 설정은 지금 쓰는 브라우저에만 저장됩니다(다른 PC나 브라우저에서는 따로 정합니다).

### 항목마다 알림 시점 따로 정하기

과제 달력의 일정, 할 일, 내 일정(행사·출장·외부활동 등)을 추가하거나 수정할 때 **알림** 칸에서 고릅니다.

- **기본 설정 따름**: 왼쪽 아래 `알림 시점 설정`에서 정한 값대로 알립니다.
- **직접 정하기**: 정시 / 10분 / 30분 / 1시간 / 3시간 / 1일 전을 고르거나, 숫자와 단위(분·시간·일 전)를 적고 `시점 추가`를 눌러 원하는 시점을 넣습니다. 여러 개를 함께 고를 수 있습니다.
- **알림 없음**: 그 항목은 시각 알림을 띄우지 않습니다.
- 시간을 정하지 않은 종일 일정(예: 종일 출장)은 그날 오전 9시를 기준으로 계산합니다. 예: `1일 전` → 전날 오전 9시.
- 과제 일정·할 일에 정한 알림은 그 과제의 연구진에게도 같은 시점에 뜹니다.

### Windows 알림으로 받기

사이트 안 팝업과 별개로, Windows 오른쪽 아래 알림(확인/닫기 단추가 있는 알림)으로도 받을 수 있습니다.

1. 위쪽의 `일정 알림` 단추를 껐다가 다시 켜면 브라우저가 알림을 허용할지 묻습니다. **허용**을 누르면 단추가 `일정 알림 켜짐 (Windows)`로 바뀝니다.
2. 묻지 않으면 주소창 왼쪽 아이콘 → 사이트 설정 → 알림을 **허용**으로 바꿉니다.
3. Windows 설정 → 시스템 → 알림에서 브라우저 알림이 켜져 있고 방해 금지가 꺼져 있어야 합니다.
4. **앱으로 설치**(Chrome: 메뉴 → 전송, 저장, 공유 → 페이지를 앱으로 설치 / Edge: 메뉴 → 앱 → 이 사이트를 앱으로 설치)하면 알림 위에 브라우저 이름 대신 `연구과제 관리`가 표시되고, 작업 표시줄에 고정해 쓸 수 있습니다.

알림은 사이트(또는 설치한 앱)가 열려 있는 동안에만 옵니다. 누를 때까지 화면에 남고, `확인`을 누르면 해당 화면으로 이동합니다.
`sw.js`, `manifest.webmanifest`, `icon-192.png`, `icon-512.png`는 이 기능에 쓰이는 파일이니 `index.html`과 같은 자리에 함께 올려야 합니다.

## 6-1-5. 반복 일정

- **어디서**: 과제 달력의 **일정 추가**(회의·일정), 그리고 **내 일정 추가**에서 종류가 **회사 업무**, **행사**, **기타**(직접 추가한 종류 포함)일 때 `반복` 칸이 나옵니다.
- **주기**: 매일 / 매주 / 2주마다 / 매월. `반복 종료일`을 함께 정합니다(비워 두면 시작일부터 1년).
- **고치기·지우기**: 반복 일정은 어느 날짜를 눌러도 **전체**가 함께 바뀌거나 지워집니다. 하루만 따로 바꾸거나 빼는 기능은 없습니다.
- **보이는 방식**: 달력에는 모든 회차가 표시되고, 첫 화면의 일정 요약과 전체 마감·할 일에는 **다음 회차 하나만** 나옵니다.
- **Google 캘린더**: 보내기를 하면 반복 규칙이 붙은 일정 하나로 들어갑니다.
- **반복되는 회사 업무**는 회차마다 따로 완료 표시합니다. 할 일 목록에는 아직 끝내지 않은 가장 이른 회차 하나만 나오고, 완료하면 다음 회차가 나옵니다.
- 과제의 할 일, 출장, 외부활동, 연가·병가는 회차마다 서류·일수 처리가 달라 반복을 넣지 않았습니다.

## 6-1-6. 오늘 일정 펼쳐 보기, 바로가기 묶음 펼침 설정

- 첫 화면 요약 줄의 **오늘 일정 n**을 누르면 그 아래로 오늘의 회의·행사·출장·할 일이 시간순으로 펼쳐집니다. 다시 누르면 접힙니다. 항목을 누르면 그 일정이 열리거나 해당 과제의 할 일 화면으로 갑니다.
- 왼쪽 **바로가기 → 관리 → 묶음 이름·순서**에서 묶음마다 `펼침`을 표시하면 처음부터 펼쳐져 있고, 지우면 접힌 채로 나옵니다. 이 설정은 연구진 화면에도 똑같이 적용됩니다. 따로 정하지 않으면 위의 두 묶음만 펼쳐집니다.

## 6-1-7. 일정 종류 추가, 끌어서 순서 바꾸기, 창 닫기

- **일정 종류 관리**(첫 화면 위쪽 단추): `종류 추가`로 내 일정의 종류(예: 학회, 강의)를 만들고 색을 정합니다. 추가한 종류는 `기타`처럼 날짜·시간·장소·반복을 넣을 수 있습니다. 지우면 그 종류의 일정은 `기타`로 옮겨집니다. 기본 7종류(회사 업무·행사·출장·외부활동·연가·병가·기타)도 이름과 순서를 바꿀 수 있고, 지울 수는 없습니다. 이름을 비우면 원래 이름으로 돌아갑니다. 이름을 바꿔도 출장 서류, 연가·병가 계산 같은 기능은 그대로입니다.
- **순서 바꾸기**: 과제 순서, 바로가기 묶음, 과제 유형, 일정 종류 모두 줄 앞의 `⠿`를 끌어서 옮깁니다. 키보드로는 `⠿`에 초점을 두고 ↑↓ 키를 누릅니다. 옮긴 뒤 `저장`을 눌러야 반영됩니다.
- **창 닫기**: 입력 창 바깥의 어두운 부분을 누르면 창이 닫힙니다. 이때 저장하지 않은 내용은 사라집니다.

## 6-2. Google 캘린더 연결

**설정 없이 되는 것 — 일정 하나씩 추가**
회의 일정 옆의 **Google 캘린더에 추가** 를 누르면 내용이 채워진 Google 캘린더 화면이 열립니다. 저장만 누르면 됩니다. 연구진도 쓸 수 있습니다.

**한 번 설정하면 되는 것 — 관리자의 Google 캘린더와 연결**
전체 캘린더 화면에서 내 Google 캘린더 일정을 함께 보고, 사이트의 회의 일정을 한꺼번에 Google 캘린더로 보낼 수 있습니다.

1. https://console.cloud.google.com 에 관리자 계정으로 들어가 위쪽에서 프로젝트 **research-shh** 를 고릅니다.
2. **API 및 서비스 → 라이브러리** 에서 **Google Calendar API** 를 찾아 **사용** 을 누릅니다.
3. 사이트의 **전체 캘린더 → Google 캘린더 연결** 을 누르고 관리자 계정을 고릅니다.
4. "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → (사이트 이름)(으)로 이동** 을 누르고, 캘린더 권한을 **허용** 합니다. 본인이 만든 앱이라 나오는 안내입니다.
   - "액세스 차단됨" 이 나오면 **API 및 서비스 → OAuth 동의 화면(대상)** 에서 게시 상태가 "테스트" 인지 보고, 테스트 사용자에 관리자 메일을 추가합니다.
5. 연결되면 **사이트 일정을 Google 캘린더로 보내기** 버튼이 생깁니다.

알아 둘 점
- 연결은 약 50분 동안 유지됩니다. 끝나면 **Google 캘린더 연결** 을 다시 누르면 됩니다. (서버 없이 쓰는 방식의 한계입니다.)
- 보내는 것은 각 과제 달력의 회의·일정입니다. 마감과 할 일은 보내지 않습니다.
- 한 번 보낸 일정은 다시 만들지 않으며, 사이트에서 고친 일정만 Google 쪽도 고칩니다. 제목은 `[과제명] 일정 이름` 으로 들어갑니다.
- Google 캘린더에서 직접 고치거나 만든 일정은 사이트의 과제 달력으로 들어오지 않습니다. 전체 캘린더에 함께 보이기만 합니다.
- Google 캘린더 연결은 관리자만 쓸 수 있습니다.

## 7-1. 디자인을 고칠 때

`index.html`의 `<style>` 끝부분에 있는 `/* Premium research workspace — visual layer only */` 아래가 화면 디자인 층입니다(색, 간격, 글자 크기, 왼쪽 메뉴 색). 디자인을 바꿀 때는 이 부분만 고치고, `<script>` 안의 기능 코드는 건드리지 않는 것이 안전합니다.
